# 06 — search, facets, sorts, random

the store UX law: **the site behaves like steam / itch.io / epic, not like a
weird experiment.** those stores all follow one pattern — a search box, a
sort dropdown, facet chips with live counts, rows with thumbnail + title +
meta. the shelf engine implements exactly that pattern. no reinvention.

## the shelf engine (pages/games.html, software.html, mods.html + search)

one JS core (LIST_JS in tools/kage_render2.py) drives all shelves and the
site search:

- **search box**: debounced (180ms), token-AND over title + series + category
  + year + caption + genres + developers + publishers + characters. URL
  param `q`.
- **facets**: GENRE / SUB-GENRE / CATEGORY / CONTENT / PLATFORM / PLAYERS /
  ERA / STATUS (03). each chip shows a live count computed against the
  current pool (facet's own group excluded — the steam behavior). clicking
  toggles a URL param; active chips render with a CLEAR ALL.
- **sorts**: name A-Z / Z-A, date new-old / old-new, size big-small /
  small-big, random (seeded — the seed rides the URL so a reshuffle is
  reproducible and shareable). nulls sink on date and size sorts.
- **rows**: thumbnail (dead-safe), title, caption line (two-line clamp),
  meta line (year · developer · genres), flag line (list, big-size, content
  walls), size estimate, OPEN → for pages / IN CATALOGUE for page-less rows.
- **state**: everything lives in the address bar. every view is a link.

## random — the scoping law

- top bar RANDOM → `pages/random.html` → picks from
  `data/random-manifest.json`: every real page (games, versions, software,
  mods) plus collections and meta-collections. total random across the site.
- a shelf's RANDOM button → opens a random page **from that shelf only**
  (rows with a page, filtered by the section). the shelf's SHUFFLE LIST
  button is the list-order randomizer (sort=random) — two different tools,
  two different names.
- the random manifest is rebuilt by every build; the fetch URL carries the
  build stamp so a stale cached manifest can never reroll old links.

## the cache law

every build gets a fresh BUILD_V (time-stamped, in kage_core.py) and stamps
it onto: css link (`?v=`), search-index fetch, random-manifest fetch. this
killed the stale-cache class of bugs ("versions pointed to CI5" was one).
never hardcode a css version again.

## the index law

`data/search-index.json` is the catalog layer: full catalog rows (games,
software, mods, collections) — **version sub-pages do not ride it**. the
random manifest is the everything layer. two files, two purposes, both
regenerated by tools/build.py on every run.
